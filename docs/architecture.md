# 架构选择

## 前台体验

首页选择教材与单元；单元页以可点读的教材图为主学习面。点击紫色圈出的英文会高亮并播放对应音频，支持慢速；单词页提供学习、中英互认、听音选义和听写练习。

## 数据优先，而非图片优先

每个可播放内容都有稳定 ID，例如 `u01-story-03`。文本、翻译、教材页码和音频路径绑定在 JSON 内，而不是绑定在图片坐标上。页面改版、音频重录或新增游戏时都可复用同一份内容。

```text
教材 PDF -> PNG 原图 -> OCR/校对 -> unit JS -> 静态网页（运行时使用 WebP）
                                             -> 朗读 m4a（正常/慢速）
                                  -> 听音/复习/测验
```

## 录音与识别的边界

静态网页可以录音：浏览器会请求麦克风权限，`MediaRecorder` 生成 WebM/Opus 文件；录音可以本地回放、删除，或导出给家长。

“识别孩子读得对不对”需要语音识别或发音评测模型。纯静态网页无法可靠地在所有手机浏览器离线完成英文发音评分：

- **本地录音模式**：零服务端、隐私最好；支持录音回放与“对照原声”，不提供评分。
- **联网评分模式（推荐）**：静态网页调用一个极小的 API；服务端将音频送到语音识别/发音评测服务，返回漏词、错词与建议。音频应即处理即删除，并在首次使用时获得家长同意。
- **浏览器实验模式**：可尝试 Web Speech API 做转写，但 iOS/微信兼容性和评分稳定性不足，只能作辅助，不能作为学习结论。

## Apple 识别模式（推荐的 iPhone/iPad 路径）

Apple 的 `Speech` framework 不是网页 API，因此不能由纯静态网页或“添加到主屏幕”的 PWA 直接调用。推荐保留本项目的 HTML/CSS/JavaScript 学习界面，再用一个很薄的 Swift/SwiftUI 壳将它作为 iOS 应用发布：

```text
网页中的“开始跟读”
  -> WKWebView 原生桥接
  -> SFSpeechRecognizer(locale: en-US)
  -> 返回转写文本、候选结果、置信信息
  -> 网页按目标句进行词级比较并显示“读对了 / 接近 / 再试一次”
```

每次识别把该题的目标词句传给 `contextualStrings`，以减少低龄学习者、专有词和短句的误识别。若设备和英语语言包支持离线识别，可要求 `requiresOnDeviceRecognition = true`；不支持时应提示用户选择“联网识别”或仅录音回放，不静默上传儿童录音。

此模式评估的是“是否说出了接近目标的内容”，不是严格的音素级发音打分。短单词和儿童发音会出现转写误判，产品反馈应分为“读对了 / 很接近 / 再听一次”，不要展示带小数的权威分数。

## 音频策略

先生成每个单词和每句话的标准语速音频，再从同一文本生成慢速版本。音频文件不直接以中文文案命名，而是使用内容 ID：

`resources/curricula/shenzhen-hj-2025-grade-2-semester-1/audio/unit-1/normal/u01-story-03.m4a`

这避免教材修订时错配，也便于将来替换为授权原声。
